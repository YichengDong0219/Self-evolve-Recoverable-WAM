# 11 ATC 自评探针：协议（2026-11-21 开跑前冻结）

用户 11-21："先做一些不用 GPU / 轻量 GPU 的探针实验，进度更新在 github 新的分支上"。
本阶段只做 CPU 分析和单卡推理，**不训练 WAM**。目标：检验 H1（冻结的自评不可靠），并为 H2（用备选动作训练后果）准备判据。
假设与整体方案见同目录 README.md。

## 数据（全部已有，不新采）
- 任务 place_mouse_pad。第一轮 DPO 的分支库：R2 策略（mouseR100v2_nv_step1573）的 188 个失败状态。
- 划分按 env_seed % 5 == 0 取测试：训练 135 个状态，测试 53 个。
- 每个状态有 8 个策略候选 chunk（种子 20261120–27），另有 0 或 1 个 cuRobo 候选，共 1682 个 chunk（1504 个策略 + 178 个 cuRobo）。
- 标签 = 该 chunk 的成功率：
  - 策略 chunk：自身分支的结局，若做过复查再加 4 次续跑；
  - cuRobo chunk：4 次续跑。
- 每个候选都有逐步仿真记录：鼠标与垫子位姿、dx/dy、持有者、是否成功。
- R2 在 σ=1 下的内部特征（fs / val / img）和 value 预测，11-14 已算好。

## 统一指标（与 11-14 的 wm_value_head2.py 相同）
- **pair_acc**：在测试状态内，取标签差 ≥ 0.5 的候选对，统计打分较高者标签也较高的比例。
- **BoN-8**：每个测试状态的 8 个策略候选中取打分最高的一个。
  - 报告三个数：选中者的标签均值（picked）、8 个候选的均值（random）、最大值（oracle）。oracle 含标签噪声，偏乐观。
  - 增益 = picked − random。95% CI 用状态级 bootstrap（2000 次，numpy 种子 0）。
- **分层**：place（第 144 步，首次松爪前）和 recovery（首次松爪后的第一个 48 步边界）。
- **方向**：FACT 的 value 越小越好，打分取 −value。

## P1 价值分解（CPU）
问题：value 主要反映“这个状态好不好”，还是“这个状态下哪个候选更好”？

对打分 s 和标签 y 各算三个量（188 个状态，只用策略候选）：
1. 状态间相关：各状态均值之间的 Spearman(s̄, ȳ)，95% CI 用状态 bootstrap。
2. 状态内相关：在每个状态内算 Spearman(s, y)，只用标签至少有两个不同值的状态；报告平均值和大于 0 的状态比例。
3. 状态间方差占比：状态均值的方差 ÷ 总方差，s 和 y 各一个。

判读（预先写定）：若状态间相关的 CI 下界 > 0，而状态内平均相关 ≤ 0.1，记为“只学到状态好坏”，支持 H1 的机制。

对象：
- R2 的 value；
- 11-14 的 ridge/fs 头，在训练状态上做 5 折交叉预测、在测试状态上做预测；
- G1 完成后，加上原版 FACT 的 value。

## P2 完美后果的上限（CPU，用特权信息）
问题：假如打分器能看到每个候选 chunk 执行完那一刻的真实状态（相当于完美想象 + 完美感知），能挑多准？

这个数是“用一个 chunk 的后果打分”的上限，也就是鼠标任务上“夹爪终点 + 垫子位置”这类特权基线的上限。

**特征**：取候选 chunk 结束时的状态，即第 48 步；若 chunk 内提前成功，取最后一步。
- dx、dy、|dx|、|dy|，以及 r = √(dx² + dy²)；
- 超出成功框的量 ex = max(|dx| − 0.015, 0) + max(|dy| − 0.012, 0)，阈值取自 place_mouse_pad 的 check_success；
- 持有者（左 / 右 / 无，one-hot）；
- 此刻是否已成功；
- 鼠标高度（相对垫子）；
- 朝向误差。

**打分器**：
- (a) 固定规则，不拟合：score = 10·[此刻已成功] − ex − 0.1·r。
- (b) 学习版：与 11-14 相同的加权 ridge，只用上面的特征；λ 由训练集上按状态分组的 5 折 CV 选择。

**报告**：pair_acc 和 BoN-8，并与 11-14 冻结特征小头的结果（BoN 增益 +0.087）对比。

**判读**：看 (a)、(b) 的 BoN 增益占 oracle 增益的比例。
- 比例高：鼠标任务上一个 chunk 的后果基本决定结局，打分瓶颈在想象和感知的精度。
- 比例低：结局主要由后续续跑决定，用单个 chunk 的后果打分，天花板就低。预期 recovery 层会偏低。

## P3 挑选空间（CPU）
- **状态级**：用 8 个策略分支各自的结局，算 pass@1（均值）和 pass@8（至少一个成功），按层报告。
- **chunk 级**：random 与 oracle（含噪）的差。

## P4 去掉标签噪声后的上限（CPU）
- 范围：至少有 2 个“n = 5”（自身结局 + 4 次复查）策略候选的状态，共 183 个；只在这些候选之间挑选。
- 方法：每个候选的 5 个结局随机分成两部分（按计数做超几何抽样），用 2 个结局挑选、用另外 3 个结局评估；重复 1000 次（种子 0）。
- 报告三个数：无偏的“用 2 次续跑挑选”成功率、同一子集上的含噪 oracle、random。

## G1 原版 FACT 的自评（单卡推理）
- **算什么**：沿用 11-14 的脚本 wm_value_feats.py 和同一份 chunk 数据集，设置不变（σ = 1，K = 4 次噪声，共用随机数，种子 0），只把 R2 换成原版 FACT（发布的 fact-wam），得到 value 和 fs / val / img 特征。
- **报告**：
  - 原版 FACT value 的 pair_acc 和 BoN-8；
  - 在原版特征上，按 11-14 流程重训的 ridge 头；
  - P1 分解。
- **H1 判读（σ = 1 一步估计层面）**：原版 FACT value 的 BoN 增益 < oracle 增益的 50% → 记为 H1 成立；≥ 50% → 记为不成立，需要用完整去噪复核（G1b，另行登记）。
- **资源**：Amax smi 4–8 中完全空闲的一张 4090（无计算进程，显存占用 < 1 GB）。不用 RTX PRO 6000，不用本机 3090。11-14 同样的计算约 5 分钟。

## G1b 原版 FACT 完整去噪的 value（2026-11-21 登记，在看到 G1 结果之后、运行 G1b 之前）
- 目的：G1 用的是 σ = 1 下的一步估计，不是 FACT 推理时 best-of-N 实际使用的 value。G1b 按 FACT 自己的推理路径重测一次。
- 做法：
  - 对 1682 个候选中的每一个，把候选 chunk 作为干净动作条件（gt_action，规范化方式与训练相同，即数据集里的 action），运行 FACT 的第二阶段，只去噪 future state 和 value，不生成未来画面（action_only）。
  - 设置与 scripts/inference_server.py 的 best-of-N 相同：20 步，guidance 0，UniPC 调度器（取自 Wan2.2 配置），flow shift 3.0。
  - 参考帧用数据集缓存的第 0 帧 VAE latent；状态与 T5 指令嵌入与 G1 相同。
  - 每个候选取 K = 4 组初始噪声，所有候选共用（种子 0，抽取顺序与 G1 相同）；打分 = −（4 次去噪结果的均值）。
- 冒烟检查（全量前）：先只跑前 16 个候选。
  - 第一步的 x0 估计应与 G1 的一步 value 高度一致：相关系数 ≥ 0.99。不满足就先查输入差异，不跑全量。
  - 去噪后的 value 应落在 [−1, 1] 附近。
- 报告与判读：与 G1 相同。BoN-8 增益 < 上限增益的 50% → 记为 H1 在完整推理层面成立。
- 资源：Amax 上一张完全空闲的 4090，预计 0.5–1 小时。

## P5 挂杯种子普查（CPU；2026-11-21 登记，运行前）
- 目的：判断挂杯的失败主要由场景决定，还是由采样决定。若主要由场景决定，换什么策略都做不成，TTS 帮不上；若主要由采样决定，就还有挑选空间。
- 数据：seeds100 上已有的全部评测结果，即 hanging_mug，demo_clean，种子 160000–160099。
  - 每个种子取其在每个“模型-存档点”上的成败。
  - 模型包括 E、E200、M、M8、M8r、R、R100、B100、B100np 及其各存档点，共 34 个；不含中途停掉的存档点。
- 统计量：
  - 每个种子被多少个模型-存档点做成的分布；
  - 从未有模型做成的种子数，以及所有模型都做成的种子数；
  - 状态间方差占比：种子均值的方差 ÷ 总方差；
  - 只看各模型最终存档点时的同样统计。
- 只做描述，不设阈值。
- 局限：不同模型-存档点不是同一个策略的独立采样，所以“有模型做成”不等于“某一个策略能采到”。

## P6 冻结特征上的非线性小头（CPU；2026-11-21 登记，用户批准，运行前）
- 问题：线性小头（+0.087）是不是已经把冻结特征里的信息读尽了？
- 特征：
  - R2 和原版 FACT 的 fs 特征，以及 all 特征（fs、val、img 三者拼接）；每种都先对 K = 4 次噪声取平均。
  - 预处理：标准化，再做 PCA 降到 128 维。PCA 只在训练状态上拟合。
- 头：两层 MLP（隐层 128，ReLU，dropout 0.2），训练细节如下：
  - 损失：按 n 加权的 MSE；
  - 优化：Adam，lr 1e-3，全批训练 300 轮；
  - weight decay 取 {1e-3, 1e-2, 1e-1} 之一，按训练状态分组做 5 折 CV 选择，选择标准是状态内、标签差 ≥ 0.5 的对的准确率；
  - 结果取 5 个随机种子的平均。
- 另做一个“状态中心化”版本：特征和标签都先减去所在状态的均值。
- 报告：
  - 测试 53 个状态上的 pair_acc 和 BoN-8；
  - 测试状态内可靠标签对（两侧 n ≥ 4）的准确率；
  - 同一口径下线性 ridge 的数字，作为对照。
- 判读：
  - 最好的非线性头相比 ridge/fs，BoN 增益高出至少 0.03，或可靠对准确率高出至少 0.05 → 记为“冻结特征未读尽”，ATC 试点的对照改用这个头；
  - 否则记为“冻结特征在线性层面已基本读尽”。

## A1 ATC 试点（训练；2026-11-21 用户批准，运行前）
- 起点：R2（mouseR100v2_nv_step1573）。候选、续跑、被训练的模型是同一个。
- 训练数据：分支库中 135 个训练状态的全部候选，每个候选一个样本：
  - 输入：第 0 帧观测，候选 chunk 作为动作；
  - 未来状态：真实执行到 chunk 末端的关节状态；
  - value 标签：raw = 1 − p，p 是该候选的续跑成功率；沿用 FACT 的 value 归一化（min −1，max 2），不加失败惩罚；
  - 样本不加权；
  - 测试状态的候选不进训练。
- 损失：只训“后果”，也就是 future state（权重 0.4）和 value（权重 0.4）。
  - 动作损失权重为 0。
  - 画面损失权重为 0：分支库里的视频是第 0 帧重复，不是真实的未来。
  - 训练窗口只取每个候选的第 0 帧（root_only 补丁）。
- 训练设置：与 R2 / E100 的 SFT 配方相同。
  - 学习率 1e-5（动作头 1e-4），warmup 100 步加 cosine，共 300 步；
  - 有效 batch 16：2 张卡 × 每卡 2 × 累积 4；
  - ZeRO-2 加 CPU offload；
  - 在 100、200、300 步各存一次。只报告第 300 步，其余存档只用来画曲线，不用来挑结果。
- 硬件：Amax smi 4–8 中两张完全空闲的 4090；不用 RTX PRO 6000，不用本机 3090。
- 评测：
  - 用 G1b 的打分脚本（20 步 action-only value 去噪，K = 4，种子 0）给 1682 个候选打分；
  - 同样流程给训练前的 R2 打分，作为“训练前”对照；
  - 在 53 个测试状态上算 pair_acc、BoN-8，以及测试状态内的可靠对准确率；
  - 对照组：ridge/fs（R2 特征）、P6 的最好非线性头、训练前 R2、原版 FACT 的 20 步 value；
  - 显著性：按状态做配对 bootstrap，给出“ATC 减 ridge/fs”BoN 增益差的 95% CI。
- 判据：
  - 差值的 CI 下界 > 0 → 记为 H2 在试点上成立；
  - 差值为正但 CI 跨 0 → 记为“不确定，需要更多数据”；
  - 差值 ≤ 0 → 记为不成立。
  - 可靠对准确率作为辅助证据。
  - 同时报告训练状态上的拟合程度，用来判断是否过拟合。
- 局限：测试集只有 53 个状态，只能检出较大的提升。
