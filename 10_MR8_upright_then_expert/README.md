# 10 · MR8 先扶正、再交给专家（分支 `mr8-upright-then-expert`，2026-11-01 起）

**思路（用户 11-01 提出）：** 杯子掉落后，先把它扶正、立在桌上，摆成专家演示里见过的样子；再交给 RoboTwin 自带的专家流程（`play_once` 用到的那组 cuRobo 原语）完成剩下的动作。扶正的位置不固定在一处，而是就近选一个方便后续接管的点，让轨迹保持多样。

**和 MR6/MR7 的区别：** MR6/MR7 要求一次抓取既能够到掉落的杯子，又能直接挂上去。杯子侧躺时，RoboTwin 的 6 个杯沿抓取点都只能沿轴线、从杯口那一侧进入，所以 MR7 的 C 档有 97.5% 的状态连一个抓取位姿都找不到。MR8 的抓取只需要做到"拿起来、立住"；挂杯交给专家，从直立的杯子开始，这正是它原本处理的情形。

## 流程（`mug_recovery_upright.py`）
1. 静置、松手、让开：同 MR6，不回零。
2. 杯子已经直立、且离架子 ≥ 12 cm 时，跳过扶正，直接交给专家。
3. 扶正候选。每只手各自枚举三类抓取：
   - **杯沿：** RoboTwin 的 6 个杯沿点，接近方向可绕手指张合轴转 0°、±30°、±60°（新增"斜向接近"），也可绕接近轴翻转 180°。
   - **杯柄 H1：** 从杯柄外侧朝杯身接近，夹住外侧竖杆（新增，几何参数从碰撞网格量得）。
   - **杯柄 H2：** 垂直于杯柄平面接近，一根手指穿过杯柄环（新增）。

   每个候选从当前关节状态开始，整条链逐段用 cuRobo 规划：预抓 → 直线接近 → 抬起 → 预放置 → 放置。
4. 放置点和朝向：
   - **放置点：** 桌面上以 4 cm 为间隔的网格点，限定在专家的工作区域内，离架子底座 ≥ 18 cm，按离杯子当前位置的远近排序。
   - **朝向：** 扶正后杯柄的朝向限定在专家场景的范围内（杯柄朝远离机器人的半平面，±90°），按手腕转动从小到大依次尝试。
5. 专家完成剩余动作。杯子立在 x > −0.05 时，走官方 S3-S4：右手抓起挂上，左手同时回原位，和 `play_once` 一致。否则走完整的 `play_once`：左手抓 → 中间点 → 右手接 → 挂。
6. 释放后保持 100 个仿真步，再检查一次成功。

## 门控（`quality_gates_mr8.py` + `sim_select_mr8.py`）
| 门控 | 内容 |
|---|---|
| G1 | 稳定成功：成功，且释放后 100 步仍成功 |
| G2 | 专家开始之前不回零（专家自身的回原位属于演示风格，允许） |
| G3 | 扶正最多抓一次 |
| G4 | 专家开始前杯子与竖直方向夹角 ≤ 15° |
| G5 | 第一次合爪前杯子位移 < 5 mm |
| G6 | 最后一次挂杯动作之前没有掉落、飞出等物理异常 |
| G7 | 单帧关节步长 ≤ 0.2 rad |
| Z | 每帧手臂状态在部署的 FACT 模型归一化下 \|z\| ≤ 5.63（第一轮审计的规则：专家最大 5.13 再加 0.5） |
| G8 | 旧的关节范围规则（专家 ∪ 前缀 ±0.5 rad）：只记录、不要求，因为扶正需要专家没用过的手腕角度 |

## 规划用的关节盒
- **MR7 盒（`jbox`）：** 专家 ∪ 失败前缀，每个关节 ±0.4 rad。
- **z 盒（`jboxz`，`mr8_joint_box_z55.json`）：** FACT 状态归一化下每个关节"均值 ± 5.5σ"。当初造成事故的绕圈（手腕 6.9 rad、基座 5.2 rad）都在这个盒子之外。

执行时，每个状态先试 MR7 盒的候选，再试 z 盒的候选。

## 冒烟测试集
从 `rf_hanging_mug_v1` 的挂杯失败中分层抽样，按 MR6 当时的结局分 4 组，每组 10 个（`results/jobs_mr8_probe40.jsonl`）：
- **K1：** 侧躺，完全找不到抓取位姿（MR7 最难的一类；81% 停在桌子后部，70% 杯口朝外）；
- **K2：** 侧躺，能抓到但整链规划不通；
- **K3：** 侧躺，MR6 有可行整链；
- **K4：** 直立。
