# 12 挂杯 TTS 最小闭环：协议（2026-11-21 冻结，开跑前）

用户 11-21：“开始执行。Amax 和集群上的空卡都可以使用”。

目标：在 hanging_mug 上跑通一轮最小闭环：原版 FACT 采样候选 → 外部 critic 看想象未来挑选 → 拼成完整轨迹 → 蒸馏 → π1 单次采样。

要回答三个问题：
1. critic 挑出来的数据是否比随机挑的更好；
2. 闭环能否提升策略本身；
3. 用真实执行结果训练“后果”，能否缩小想象与现实的差距。

## 设定（用户确认“开始执行”时采用的默认值）
| 项目 | 设定 |
|---|---|
| 任务 | hanging_mug，demo_clean |
| 基座 π0 | 原版 FACT（fact-wam）；seeds100 上为 42，逐种子结果已有 |
| 训练种子 | 第 0 轮：从 170000 起、专家检查通过的前 100 个；第 1 轮：从 175000 起的前 100 个 |
| 评测种子 | seeds100（与训练种子不重叠） |
| 候选 | 每个 48 步 chunk 采 N = 8 个，种子为 seed_for(20261121, 起点, 'candidate', 决策序号, i)；每个 chunk 都做挑选 |
| 推理服务 | 由带 SHA 校验的 FACT inference_server.py 副本打补丁生成，FACT 仓库本身不改 |
| 服务参数 | 20 步，guidance 0，flow shift 3.0，return_images |
| 服务返回 | 8 个候选的动作、想象关键帧（+12/+24/+36/+48 步），以及 FACT 自带的 value（作为对照） |
| 折扣 | γ = 0.9，按 chunk 计 |

## 第 0 轮（随机挑选；同时作为对照 C 的数据来源）
- 在线：8 个候选中均匀随机挑一个执行；随机种子由决策序号确定。
- 在线记录：环境种子、已执行动作、每个 chunk 边界的状态（关节和全部物体位姿）、三视角画面、8 个候选的动作与想象画面、整局成败。

## 离线处理（每一轮都做）
1. **补执行候选**：从环境种子逐位重放到每个 chunk 边界，核对状态与在线记录一致（不一致则丢弃并计数），然后把其余 7 个候选各执行 48 步，记录 +12/+24/+36/+48 步的三视角真实画面和状态。
2. **PRM**：Robo-Dopamine GRM-2.0-8B，从 hf-mirror 下载，冻结使用，单独建 conda 环境。
   - 输入三视角画面，目标图留空。
   - 只用两种模式：incremental 得到 hop（两状态之间的进度变化），forward 得到 Φ（相对本局起点的绝对进度）。
3. **V**：
   - 输入：Φ(s)、上一段的 hop、已用步数 / 步数上限、两只夹爪的开合。
   - 模型：逻辑回归。
   - 标签：轨迹上每个 chunk 边界的折扣成功 return，G_t = γ^(T−t)（第 T 个 chunk 内成功），失败为 0。
4. **Q（critic）**：
   - 特征：hop(s → 想象 +48)、Φ(想象 +48)、Φ(想象 +24)、候选内左右夹爪开合指令的变化、每只手臂关节空间位移的 L2。
   - 标签：若该 chunk 内成功则为 1，否则为 γ·V(s′)，其中 s′ 是该候选真实执行后的状态；8 个候选统一用这一种标签。
   - 损失：组内 softmax 交叉熵（τ = 0.1）加 0.1 倍 MSE。
   - 模型：标准化特征上的线性模型；L2 强度按场景分组做 5 折 CV 选择，选择标准是组内两两比较准确率。
5. **门槛**：随机抽 10% 的决策状态（种子 0），把 8 个候选都从 s′ 用 π0 续跑到结束（各 1 次），得到真实结局。在这批状态上：
   - critic 的 8 选 1 增益 = 被选中候选的真实结局 − 8 个候选真实结局的均值；
   - 按状态做 bootstrap，95% CI 下界 > 0 才进入第 1 轮；否则停下报告，同时给出 V 的 AUC、PRM 在真实 s′ 上的排序能力、想象与真实排序的一致性。

## 第 1 轮（critic 挑选）
- 取 Q 分数最高的候选，平分时随机；其余流程与第 0 轮相同，也包括离线补执行。

## 蒸馏：三组，都从 π0 出发
- **配方**：沿用 mug_sft_novalue（value 关闭，与之前的 E 组可比）。
  - 成功轨迹训练动作、画面、未来状态；
  - 失败轨迹屏蔽动作损失，只训练画面和未来状态。
- **分组**：
  - C：第 0 轮的轨迹；
  - A：第 1 轮的轨迹；
  - B：A，再加上未被选中候选的一个 chunk 片段（真实画面，屏蔽动作损失），采样量为拼接轨迹的 0.5 倍。
- **不混入专家演示回放**：只用 100 条专家演示，E 组就能从 42 升到 69，混入会掩盖自采数据本身的效果。E 组作为外部参照。
- **训练参数**：2000 步，有效 batch 32（2 卡 × 每卡 2 × 累积 8），学习率 1e-5 / 1e-4，warmup 100 步后 cosine，ZeRO-2 加 CPU offload。在 1000 步和 2000 步存档。

## 评测
- seeds100，单次采样，三组的 1000 步和 2000 步存档都评测。
- **主比较**（2000 步，与 π0 逐种子配对，McNemar 检验）：A vs C、A vs π0、B vs A。
- **次要指标**：
  - 第 0 轮与第 1 轮 TTS 本身的成功率（各自的训练种子）；
  - critic 指标；
  - 想象与现实的差距：B 组 SFT 前后，在留出候选上比较想象与真实的排序一致性；
  - 失败阶段分解。
- **功效说明**：100 个配对种子只能检出约 10 个百分点以上的差距。如需扩大评测，必须在看到结果之前决定。

## 实现细节补充（2026-11-21，写于第 0 轮正式运行之前）
1. **PRM 输入**：
   - 所有送给 PRM 的画面（真实的和想象的）都统一成 FACT 拼图的尺寸：头部 256×192，两个腕部各 128×96。真实画面用 PIL 双线性缩放；想象画面直接从 [192, 384] 的拼图上切出三块。
   - 参考起点 = 本局第一帧的头部画面；参考终点 = Robo-Dopamine 自带的空白目标图。
   - 提示词与消息格式原样照搬官方 examples/inference.py（2c714ab）。解码用贪心（temperature 0），保证结果可复现。
2. **种子**：
   - 第 0 轮：扫描 170000–170139，按升序取前 100 个通过专家检查的种子；其余的不进入分析。
   - 第 1 轮：同样做法，扫描 175000–175139。
3. **门槛检查的状态必须来自留出场景**：
   - 第 0 轮的 100 个场景按种子升序排列，每隔 5 个取 1 个，共 20 个作为留出场景；
   - 从留出场景的决策状态中随机抽 70 个（种子 0，约占全部状态的 10%）做续跑；
   - 门槛评估用的 V 和 Q 只用另外 80 个场景训练；
   - 门槛通过后，按交叉验证选出的超参，在全部 100 个场景上重新拟合，作为第 1 轮的 critic。
4. **续跑策略**：π0 的标准快速模式（前缀缓存，跳过未来状态和 value）；续跑种子按决策序号对齐。
5. **时间折算**：第 T 个 chunk 指包含成功那一步的 chunk，T = (steps − 1) // 48。

## 补充二：门槛独立重测（2026-11-22 10:30 写定，重测开始之前）
**背景**：第一次门槛在 70 个留出状态上得到 critic 增益 +0.0375，95% CI [−0.0018, +0.0840]，未通过（`results/critic_gate.json`）。用户 11-22 决定：用剩余的留出状态独立重测。

1. **critic 冻结**：直接使用第一次门槛的 V 和 Q（`r0/critic_gate.json`，sha256 `7bf7491773dbbf4f91628beb2625ba9f9c1e34e39761e578d8f987a1e1d9cbd8`，只用 80 个非留出场景训练），不重新拟合、不调参。
2. **状态**：20 个留出场景的全部 296 个决策状态中，去掉第一次用过的 70 个（`gate_pairs.json`，sha256 `c02eb8aef05761c93b607d557c03e1ef9e33d0347e501801fca9039e7ac55245`），剩下的 226 个全部使用，不再抽样（`gate_pairs_retest.json`，sha256 `0f22363cd290d470d58ca3f1945e8bc441a23a8351f62d6d29f5b068fc145798`）。
3. **续跑**：与第一次完全相同——每个候选真实执行 48 步后交给 π0（标准快速模式服务，完整观测）续跑到结束，每个候选 1 次，续跑种子按决策序号对齐；每张卡一个服务配一个续跑进程（Amax smi 4–8、集群 0–3）。
4. **主判据（决定是否进入第 1 轮）**：只在这 226 个状态上计算，**不与第一次的 70 个合并**。8 选 1 增益 = critic 选中候选的真实结局 − 8 个候选真实结局的均值；按状态 bootstrap（numpy default_rng(0)，2000 次，状态按 (种子, 决策序号) 排序，与 `critic_train.py` 相同）；95% CI 下界 > 0 才算通过。评估脚本 `gate_eval.py` 在第一次的 70 个状态上逐位复现了第一次的结果。
5. **次要分析（只描述，不用于决策）**：决策序号 0–4 / 5–9 / ≥10 分阶段的增益（第一次的结果提示 0–4 阶段增益较大，作为次要假设）；随机挑选的置换检验 p 值；结局有分歧的状态数；只用 PRM 特征挑选的增益；与第一次 70 个状态合并后的 296 个状态的增益（仅描述）。
6. **功效**：按第一次估计的单状态增益标准差约 0.18，226 个状态的标准误约 0.012；若真实增益为 0.0375，检出概率约 86%。
7. **数据完整性**：任何状态，只要续跑日志里出现渲染错误（OIDN、DeviceLost、cannot create buffer、out of memory）或服务端报错，就把它的全部结果归档并重跑一次；仍不完整的状态如实报告并排除。
8. **结论**：
   - 通过：先向用户报告，再按交叉验证超参在全部 100 个场景上拟合 critic，进入第 1 轮。
   - 不通过：放弃这一版 critic，下一步方向与用户商定。
